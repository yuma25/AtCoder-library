# 競技プログラミング：コンテナ選択ガイド

競技プログラミング（キョウプロ）で「どのデータ構造を使うべきか」を判断するための比較まとめです。

---

## 1. シーケンス系 (データを並べて管理)

| コンテナ | 内部構造 | 特徴 | キョウプロでの主な用途 |
| :--- | :--- | :--- | :--- |
| **`vector`** | 動的配列 | ランダムアクセスが最速 ($O(1)$)。末尾以外への挿入は遅い。 | **迷ったらこれ。** データの保持、ソート、累積和、全探索。 |
| **`deque`** | ブロック配列 | **先頭と末尾**の両方で追加・削除が $O(1)$。 | スライディングウィンドウ最小値、BFSのキュー。 |
| **`string`** | 文字配列 | `vector<char>` に近いが、文字列操作（結合・検索）に特化。 | 文字列問題全般、巨大な数字の保持。 |

---

## 2. 集合・連想配列系 (検索と順序を管理)
※すべて内部は「平衡二分探索木」で、基本操作は **$O(\log N)$** です。

| コンテナ | 重複 | 順序 | 特徴 | キョウプロでの主な用途 |
| :--- | :--- | :--- | :--- | :--- |
| **`set`** | なし | 昇順 | 値の存在を高速に判定。 | 重複削除、値の存在判定。 |
| **`map`** | なし | 昇順 | キーと値を紐付け。 | データの集計（出現回数カウント）、座標圧縮。 |
| **`multiset`** | **あり** | 昇順 | 重複した値を保持しつつ、常にソート状態。 | 動的なデータの最小・最大値管理。 |

---

## 3. コンテナアダプタ (入り口と出口を制限)

| コンテナ | 規則 | 特徴 | キョウプロでの主な用途 |
| :--- | :--- | :--- | :--- |
| **`stack`** | LIFO | 後入れ先出し。 | 括弧の対応、DFS（非再帰）。 |
| **`queue`** | FIFO | 先入れ先出し。 | **BFS（幅優先探索）**。 |
| **`priority_queue`** | 優先度 | 常に最大（または最小）がトップに来る。 | **ダイクストラ法**、貪欲法。 |

---

## 4. 特殊・ユーティリティ

| コンテナ | 特徴 | キョウプロでの主な用途 |
| :--- | :--- | :--- |
| **`bitset`** | ビット管理 | メモリ節約 ＆ ビット演算により約64倍高速化。 | 部分和問題 (bitset DP)、フラグ管理。 |
| **`pair` / `tuple`** | 組 | 異なる型の値を一つにまとめる。 | 座標 `(x, y)` の保持、ダイクストラ法の `(距離, 頂点)`。 |

---

## 💡 選び方の鉄則

1.  **「とりあえず」なら `vector`**: ほとんどのケースで `vector` が最も効率的です。
2.  **「先頭から消したい」なら `deque`**: `vector` で先頭を消すと $O(N)$ かかりますが、`deque` なら $O(1)$ です。
3.  **「存在確認・二分探索したい」なら `set`**: `vector` でも二分探索はできますが、途中で値が追加される場合は `set` が必要です。
4.  **「最小値・最大値だけ知りたい」なら `priority_queue`**: 中身をすべてソートして保持し続ける必要がない場合は、こちらの方が高速です。
