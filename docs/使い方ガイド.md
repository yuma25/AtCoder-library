# AtCoder 自動化環境 使い方ガイド

このガイドでは、構築した環境を最大限に活用するための日常的な操作方法を解説します。

---

## 1. 推奨されるディレクトリ構成

リポジトリ直下の `ABC/` フォルダ内に各コンテストの問題を管理します。

```text
atcoder-library/
├── ABC/                   <-- [A] コンテスト取得の起点
│   ├── abc350/
│   │   ├── a/             <-- [B] 実装・テスト・提出の場所
│   │   │   ├── main.cpp
│   │   │   └── tests/
│   │   └── ...
├── docs/
├── templates/
└── ...
```

---

## 2. コンテスト中の基本フロー

### ① コンテストの準備 (場所: [A])
コンテストが始まったら、`ABC/` フォルダへ移動して問題を取得します。

```bash
cd ~/github/atcoder-library/ABC
acc new abc350
```

### ② 実装とテスト (場所: [B])
解きたい問題のフォルダへ移動し、コードを書きます。

```bash
cd abc350/a
# (VS Code 等で main.cpp を編集)

# サンプルテストの実行
oj t
```

### ③ 提出 (場所: [B])
テストが通ったら提出します。

```bash
acc submit
```

---

## 3. 言語の切り替え方法

デフォルトでは C++ に設定されていますが、状況に応じて Python 等に切り替えられます。

### A. 今回だけ特定の言語を使いたい
`acc new` の時にオプションを付けます。

```bash
# Pythonテンプレートで作成
acc new abc350 --template python
```

### B. 今後のデフォルト言語を変更したい
設定コマンドで永続的に変更できます。

```bash
# Pythonをデフォルトにする
acc config default-template python

# C++をデフォルトに戻す
acc config default-template cpp
```

## 4. トラブルシューティング

### 「ログインしていない」と怒られる
Cloudflareの影響でセッションが切れることがあります。その場合は[環境構築ガイド](../tools/環境構築ガイド.md)の「ログイン設定」を参考に、`REVEL_SESSION` を再設定してください。

### テストが通らない
- **コンパイルエラー**: `g++` の構文エラーがないか確認してください。
- **WA (Wrong Answer)**: ロジックを確認してください。`tests/` フォルダの中身を見ることで、どのサンプルで落ちたか確認できます。

### 提出できない
`acc submit` が動かない場合は、`oj login --check https://atcoder.jp/` でログイン状態を確認してください。
